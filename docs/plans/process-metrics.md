# 过程指标周报 + 技能成败回填:Owlery 的内生评测层

**状态**:2026-11-16 成文,排期待用户定(不插队面试弹药;与 Super-agent L1 不抢档期,边界见 §5)。

## 1. 目标

两件交付,合为一场小战役:

1. **过程指标周报**:一个只读脚本,从生产库算出固定指标集,产出 markdown 周报落盘;可挂 Owlery Schedules 每周自动跑。零模型调用。
2. **技能成败回填**:技能(skill)被使用后的任务成败回流为该技能的"涉败"记录;涉败率过阈值自动生成**修订/废弃候补**进现有人审队列。补上经验沉淀闭环缺失的"选择压力"一环。

## 2. 动机

- 评测战线收官结论(2026-11,gaia-pilot + terminal-bench 两案):benchmark 对比测不出 harness 价值、第三方榜无开放通道;行业标准做法=内部过程评测+可复现。Owlery 的说服力载体是台账,本案把台账从"故事+单点数字"升级为"有趋势的指标曲线"。
- 数据地基已成:harness_exits(turn 死因,attempt-replay 战役)、task_runs/attempts、委派失败分类、turn_usage 成本——8 月田野报告已从中挖出 51.1% 复核抓伤率、37.9% 重试率等数字,证明可挖;缺的只是从一次性挖矿到常态指标。
- 技能侧:经验沉淀 v1/v2 建成"产生→人审→落地→use_count",但 use_count 只计次不计成败,坏技能与好技能在货架上同貌——治理闭环的预留缺口(experience-consolidation 定案"等真实腐化案例驱动"),本案把管线建好。

## 3. 设计要点

### 3.1 指标集(口径预注册,沿田野报告基线)

- **一次通过率**:completed 且 attempt=1 且无 blocked 史的任务占比;
- **重试率** 与 **人工接管率**(重试中需人工 unblock 的占比);
- **turn 死因分布**:harness_exits.reason 六分类占比;
- **委派失败率**(按 delegation_runs 失败分类);
- **每任务成本**:turn_usage 聚合(claude 侧;codex 成本字段不可用的事实照田野报告口径声明);
- **技能涉败率**(§3.3 产出)。

口径一旦首报即冻结;改口径=新版本号并在报告中并列旧口径,禁止静默改算法。

### 3.2 周报形态

- 只读:对生产库做 backup API 快照后计算,零写生产(田野报告同款安全惯例);
- 产出 markdown 落盘(含本期数字+历史趋势表),脚本放 `benchmarks/process-metrics/` 或 `scripts/`(执行者定);
- 可注册为 Owlery Schedule 每周自动跑;
- **不做 UI 页**——等周报被真实读用一个月再议(§6)。

### 3.3 技能成败回填(归因口径,预注册)

- **不做因果归因**(判定"这次失败是该技能的锅"不可靠),做**共现统计+人工裁决**:
  - 调用过技能 S 的 Task Board run 终局为 fail/blocked(排除纯环境死因,如 watchdog/interrupted,口径细节执行者定并写死)→ S 记一次"涉败";
  - 触发线:**涉败率 ≥ 50% 且总调用 ≥ 3** → 自动生成 S 的修订/废弃候补,进现有 skill candidate 人审队列,候补正文附涉败 run 清单(链接审计回放)作证据;
  - 机器只负责"举手",是否真是技能的锅、修订还是废弃,由人审判——与经验沉淀"机器管发生、人管留下"同构,错杀风险收敛到人审侧。
- 数据写点仅一处:候补生成,复用现有 candidate 机制,不新建存储/注入通道。

### 3.4 数据层约束

- 指标脚本**只读现有表**,无新埋点、无 schema 变更;
- 技能回填需要的调用↔run 关联若现表已可推导则直接用,确需补列须先在卡面评论报 Albus 过目再动。

## 4. 验收判据(预注册冻结)

1. 周报脚本对生产快照跑出 §3.1 全部指标,其中可对账项与田野报告底稿口径核对一致(允许因时间窗不同数字不同,口径必须同);
2. 技能涉败端到端试金石:构造一个涉败超阈值的技能场景,候补自动出现在人审审查页,带涉败证据链;
3. 周报经 Schedule 真实自动产出至少一期;
4. 四道测试门全绿(技能回填触产品代码)。

## 5. 与 Super-agent L1 的边界

- L1 Trace 视图=**单链路纵剖面**(一个 trigger 从起点到终态),解决余步搁浅;本案=**全体任务横截面**(聚合统计与趋势),解决评测与说服力。产出正交,不合并、不互相依赖;
- 数据源有重叠(task_runs/harness_exits),读取逻辑若 L1 先建可复用,但本案不等它;
- L1 的 triggers 表落地后,"余步响应率"可作为后续新增指标——本案 v1 不含。

## 6. 不做

- UI 指标页/实时看板(周报被真实读用一个月后再议);
- LLM judge 轨迹质量判分(贵且自说自话风险);
- MAST 式失效分类标注(等失败样本量成规模再议);
- 任何自动生效:涉败候补一律过人审,沿 experience-consolidation 定案;
- 对外宣传数字的自动输出(周报是内部台账,外用须经人工摘编)。

## 7. 时间盒

一周封顶(指标脚本 2 天 + 技能回填 3 天 + 验收);与求职活动冲突时无条件让位。
