# GAIA 侦察盒:Owlery vs 裸 Claude Code 的 benchmark 分差验证

**状态**:侦察(时间盒 3 天 / 预算 $80 封顶)。这不是 eval 基建立项——输出只有一组数字和一个按 §4 预注册判据作出的判定。

## 1. 目标

回答一个问题:**Owlery 相比裸 Claude Code,在标准 agent benchmark(GAIA)上有没有"可以对外宣传"的分差?**

三个可能出口,各自的后续动作在 §4 写死。

## 2. 动机

自进化讨论(2026-11)的延伸分歧:用户认为重点项目必须有常规 benchmark 评测才能说服外人;Albus 认为 Owlery 的长处(记忆/技能沉淀/治理)是跨任务属性,一次性考题用不上,预测分差不显著。双方都没有数据。本侦察花小钱买数据,终结这个分歧——与 factor-mm venue-screener、A 股零成本侦察同一方法:先侦察,数字说话,判据预注册防无限加注。

## 3. 设计要点

### 3.1 题源与抽样(防挑题)

- GAIA **validation** split(答案公开,HF gated dataset,需同意条款后下载;`gaia-benchmark/GAIA`)。
- 过滤规则(写死):排除附件为音频/视频(.mp3/.wav/.m4a/.mp4 等)的题;文本、图像、表格、PDF 附件保留(Claude Code 的 Read 工具两边同等可读)。
- 过滤后用**固定随机种子 seed=42** 均匀抽样:Level 1 抽 9 题 + Level 2 抽 6 题,共 15 题。不抽 Level 3(两边大概率都 0 分,浪费预算)。
- 抽样脚本和抽中的 task_id 清单在跑任何一题之前先提交(commit),之后不得更换题目。

### 3.2 两个条件

| | A:裸基线 | B:Owlery |
|---|---|---|
| 入口 | Claude Code CLI,每题全新会话 | Owlery session(新建一个无历史记忆的考试 agent) |
| 可用能力 | CLI 内建工具(WebSearch/WebFetch/Read/Bash) | 同左 + Owlery 全家桶(委派、bg、skills、连接器) |
| 模型 | 同一 model id,两边 pin 死 | 同左 |
| prompt | 同一模板:题面 + 附件路径 + 「最后一行输出 FINAL ANSWER: <answer>」 | 同左 |

- 公平上限:**每题单 run,上限 $2 或 50 turns,先到为止**;超限按 0 分计,成本照记。
- 不做 Avg@3(预算限制);单次运行的波动风险由 §4 的 3 题底线吸收。
- 跑的是 **Owlery 现状**,禁止为刷分调优(不新写 skill、不改 prompt、不配考试专用工具)。
- 数据污染(validation 答案公开、模型可能见过)对两边对称,不影响相对比较,结论只谈相对分差不谈绝对分。
- 执行在开发机,不占生产机 quota。

### 3.3 判分与记账

- 按 GAIA 官方 quasi-exact-match 规则脚本判分,不人工判。
- 每题记录:对错、token 用量、美元成本、turn 数、墙钟时间。两条件汇总对比。
- 所有原始输出存档(每题每条件一个文件),结论必须可从存档复算。

## 4. 预注册判据(冻结,跑完不得修改)

以 15 题中 Owlery 净胜题数(B 对而 A 错的题数 − A 对而 B 错的题数)为准:

1. **净胜 ≥ 3 题,且 B 平均成本 ≤ 2× A** → 有宣传价值的信号,扩到 50 题做确认轮(另立侦察,仍预注册)。
2. **|净胜| < 3 题** → 定案「无宣传价值」,benchmark 宣传线封盘;分歧判 Albus 预测成立,此后对外说服统一走生产台账口径。
3. **净胜 ≤ −3 题(Owlery 输)** → 同上封盘,结果留档自用,不外传。

**禁止条款**:不得换题集重抽、不得赛后改判据、不得挑单次好结果重跑、不得以"再调调 Owlery 再试一次"续盒。时间盒(3 天)或预算盒($80)任一打穿而未跑完 → 侦察失败如实报告,已有部分数据不得当完整结论用。

## 5. 不做

- 不建 eval 基建(无 CI 集成、无常驻考场、无题库扩充)。
- 不跑 SWE-bench 或其他 benchmark(修代码题裸 CLI 本来就强,Owlery 加成最小,不是分歧所在)。
- 不把结果写进 README/简历——判定出来后由用户另行决定用不用、怎么用。
- 不做多模型对比、不做 Avg@3、不做消融。
