# 失败回路:无评分器工作流的跨任务自优化

**状态**:2026-11-17 成文,用户拍板「必须搞自进化」后的落地任务书。排期用户定;与求职活动冲突无条件让位;与 Super-agent L1 不同时开。

**依赖**:过程指标战役已并 main(PR #22,`benchmarks/process-metrics/` 一带的只读扫描与技能涉败回填基建)。本案是它的直接续篇。

## 1. 目标

Owlery 的自进化 = 变异 + 选择压力 + 度量。三件套在**技能层**已经齐了:经验沉淀三通道产生变异,涉败回填施加选择,过程指标周报做度量。本案把**选择压力扩到剩下两层对象**,补成完整的失败回路:

- **规约层**:CLAUDE.md 规则、任务书模板。同一失败签名跨任务重复出现 → 系统自动起草规约修订候补(diff 或新规则草稿),附证据链,进人审。
- **人设层**:agent 的 system prompt。失败聚类定位到某个 agent 的重复性失误模式 → 起草该 agent 的人设 diff 候补,进人审。(这是 11-13 被排序靠后的「方案 B」——当时否它的理由是无验证信号易成仪式;失败聚类就是那个验证信号,故带条件复活。)
- **技能层**:已交付,本案不重做。唯一动作是把失败签名证据并入涉败候补的正文,不另起炉灶。

「自己优化」的定义在此冻结:**系统自己提案,人一键批准后生效**。不是自动生效。

## 2. 动机

- **学界地图的空白**:2026-11 扫完五篇工作流自进化论文(AFlow→MASS→EvoFlow→EvoTeam,旁支 EvoMAC),全部前提是打分任务流——要么设计期靠验证集刷分,要么任务内靠单测反馈。没有一篇处理「无评分器的真实生产工作流如何跨任务持久优化」。失败回路是这个空白的诚实答案:真实工作流没有分数,但有**失败**,失败就是免费的选择信号。
- **Owlery 的现状缺口**:规约和人设至今只进不出。CLAUDE.md 的规则越写越多,没有机制挑战一条过时的规则;agent 人设自建立后只靠人偶然发现问题才改。坏规则和好规则在货架上同貌——这正是 11-13 对技能层的诊断原文,技能层治了,这两层还没治。
- **人肉路径的实证**:multi-agent-contention 手册里六种死法、CLAUDE.md 里「past sessions repeatedly took the shortcut」——这些规约全是人工验尸后手写回去的,路径 100% 靠人肉且依赖人恰好在场。失败回路把其中「发现重复模式 + 起草修订」两步机械化,人只保留裁决权。
- **数据地基已成**:harness_exits(turn 死因六分类)、task_runs/attempts(重试与 blocked 史)、委派失败分类、审计回放(每个 turn 死得有解释)——过程指标战役已证明这些表可挖且口径能冻结。

## 3. 设计要点

### 3.1 失败签名

结构化签名,从现有表只读推导,例如由(终态类型、死因分类、涉事 agent、失败阶段)组成,blocked/fail 的原因文本做轻量聚类归并。两条纪律:

- 签名设计细节执行者定,但**必须先预注册写死再跑**,禁止边跑边改口径(过程指标战役同款纪律);
- 纯环境死因(watchdog 误杀、interrupted 等)按涉败回填同口径排除,不入签名统计。

### 3.2 聚类与触发线

- 同签名跨 run 计数;触发线预注册(方向:同签名 ≥3 次且跨 ≥2 个不同任务——具体数字执行者在卡面与 Albus 议定后冻结);
- 触发后由模型读相关 run 的审计回放摘要,起草修订候补:判断该失败模式指向哪一层(规约 / 人设 / 既有技能),产出对应形态的草稿 + 证据链(涉案 run 清单,链接审计回放);
- 判层判不准没关系——候补正文把三层都列为选项交人裁决,机器不硬分。

### 3.3 候补通道(复用为先,禁新建注入通道)

- **规约层候补**:CLAUDE.md / 任务书模板修订走 branch+PR,同任何普通变更——候补的形态就是一个起草好的 PR 或待人转 PR 的 diff 文件;
- **人设层候补**:agent 人设 diff 候补过人审后应用。优先核实复用 skill candidate 审查页形态的成本;复用不划算就建极简审查入口,但**任何形态都禁自动生效**;
- **技能层**:走既有涉败回填候补,只补证据。

### 3.4 归因纪律

同涉败回填:**不做因果归因,机器举手、人判锅**。候补正文必须写明「此为共现证据,非因果结论」。错杀风险收敛到人审侧,这是整条线三次裁定不动摇的治理底线。

### 3.5 运行形态与防骚扰

- 挂 Schedule 周跑(与过程指标周报同节奏,可同脚本家族,执行者定);无新失败积累则零产出零打扰;
- **驳回记忆**:人拒绝过的候补,同签名进入冷却,不得重复提案;重新举手的唯一条件是签名计数显著新增(阈值预注册)。没有这条,失败回路会退化成每周骚扰机。

### 3.6 数据层约束

只读现有表为默认;确需补列或新表(如签名计数、驳回冷却记录),先在卡面评论报 Albus 过目再动。

### 3.7 起草纪律与生效后追踪(提示词如何优化)

学界自动提示词优化器(MASS 一三阶段、DSPy、GEPA、OPRO、TextGrad)全以打分器为梯度,Owlery 没有,不装(见 §5 方案 C)。无打分器环境下,提示词修订的质量来自纪律,验证来自失败流本身:

- **最小 diff,一次一变量**:每个候补只动一处;一次改多处,后续签名变化无法归因到单个修订;
- **删除权平等**:提示词的常见病是只进不出(CLAUDE.md 规则越摞越厚)。候补的合法形态包括「删掉这条过时规则」,与「新增规则」平等——MASS 的实证侧写:优化后的提示词往往更短更具体;
- **生效后追踪(本案的验证闭环)**:候补被批准生效后,其针对的失败签名进入观察期(时长预注册,如 2–4 个周报周期);**同签名计数的前后对照就是该次修订的唯一诚实验证**——用生产失败流当免费测试集。签名归零或显著下降=有效;不降=系统自动举手「修订未起效」供人复裁,人可选择回滚(规约=revert PR、人设=还原 diff)或再修。没有这条,回路只会提案不会认错,提示词只会单向膨胀。

1. 失败签名聚类对生产库历史数据跑通,且能把已知的真实重复失败案例(六种死法中有数据印迹者,如 watchdog 系)聚成签名——以史料验证签名设计不是空转;
2. 端到端试金石:构造跨任务重复失败场景 → 候补自动出现在人审侧,附证据链;人批准后真实生效(规约=PR 可合、人设=diff 可应用并在该 agent 下一次 spawn 生效);
3. 驳回试金石:人拒绝候补后,同签名在冷却期内不再提案;
4. 追踪试金石:构造「修订生效后同签名仍复发」场景 → 系统自动产出「修订未起效」复裁提示,附前后计数对照;
5. 四道测试门全绿。

## 5. 不做(历次裁定汇总,翻案条件随附)

- **拓扑/派单自动化**:MASS 论文级证据=增益大头在提示词、拓扑是小头;且 N=4 固定三角无搜索空间。(翻案:agent 数量级增长出现真实变阵需求。)
- **去人审自动生效**:翻案条件=人审队列积压的实据,现队列近空。
- **评测驱动闭环 / eval 基建**(方案 C):三次否定——eval-env 原案死因、GAIA 侦察盒判据②、AgentBeats 闸 2 收官。失败回路的全部意义就在于不需要它。
- **任务内文本反向传播**(EvoMAC 式):attempt+Snape 复核已内置等价循环;「文本梯度」是弱模型时代的能力补丁。
- **记忆巡检 / TTL**:记忆是策展,不做机械老化。
- **LLM judge 全轨迹判分**:贵且自说自话。

## 6. 时间盒

一周封顶(签名+聚类 3 天、候补起草与通道 2 天、验收)。求职冲突无条件让位。
