# 经验沉淀（experience consolidation）

## 1. 目标

让「走通的路径」和「踩过的坑」在任务收官时被机制化捕获，并分流进三条
**已有的**复用通道（agent 记忆 / CLAUDE.md / skills），使同一个 agent
不再重踩同一个坑、不再重新考古自己走通过的流程。

## 2. 动机

两个真实事故：

- **Task Board attempt 验尸**：同类死因（headless 后台丢输出、终验收跑门
  打勾不重推导）在多个任务重复出现。教训只存在于 Albus 的记忆里；干活的
  worker 是阅后即焚的 session，不复盘就带着教训一起死。
- **Aberforth 的 hermes PR 路径**：向外部仓提 PR 的完整流程走通过一次，
  未固化；数月后重走时坑全部重踩。典型的程序性记忆丢失。

外部调研（2026-08-31 深研 9ca03bcca32a）结论支持本设计方向：

- 无治理的全自动记忆写入会退化——Mem0 官方承认低相关条目累积损害检索；
- 「从走通的轨迹归纳可复用 workflow + 选择性注入」被 AWM
  （arXiv 2409.07429）证明有效（WebArena 相对提升 51.1%）；
- SKILL.md 是跨工具事实标准，Claude Code 原生加载；官方
  `anthropics/skills` 的 skill-creator 提供半自动提炼的引导循环，可借鉴；
- 程序性记忆需要修正/淘汰环节（Memp，arXiv 2508.06433），否则技能库随
  时间腐化。

## 3. 设计要点

### 3.1 脊梁

**机制管「复盘必须发生」，人管「什么值得留下」。** 不新建存储通道、不新
建注入引擎；复用三条现有通道，它们已经各自是机器注入，入口收在人的策展
手里：

| 通道 | 注入面 | 载体 |
|------|--------|------|
| agent 记忆 | 本人（MEMORY.md 索引随 session 加载） | 一事一文件 |
| CLAUDE.md | 全员（随 repo 加载） | 规则段落 |
| skills | 按需调用 | SKILL.md 标准 |

### 3.2 触发（机制层）

- **Task Board**：任务走到终态时，若**非一次通过**（attempts > 1、有
  blocked 历史、复核 verdict=fail、或被打回重做过），机制化注入复盘环
  节（在 `complete` 之前拦或之后追加复盘 turn，由执行者研究定）。一次
  绿过的任务跳过——没有经验可沉淀，这条是防复盘疲劳的分水岭。
- **delegation**：子会话终局适用同一判据。注入点由执行者研究；若实现成
  本与 Task Board 路径不成比例，允许本期只做 Task Board，但须在交付说
  明中写明这一收窄。
- **常任 agent**（Albus/Aberforth 等）：无终态钩子可挂，走人设条款——凡
  走通一条多步外部流程（如向外部仓提 PR 的全流程），收官时必须自问
  「这条路径下次还要走吗？」，要则当场固化为 skill 候补或程序性记忆。
  各常任 agent 的人设 prompt 相应增补。

### 3.3 分流协议（复盘的三问）

复盘产物必须落到且只落到三条通道之一：

1. 只关我这个 agent 的**判断性教训** → 写本人记忆（一事一文件，更新旧
   文件优于新建）；
2. **全员都该知道的规则** → 提名 CLAUDE.md 候补，走 PR，人审合入；
3. **可重复的多步流程** → 提名 skill 候补（SKILL.md 草稿），人审后落地。

worker 在场时自己写——它拥有全轨迹上下文；不派二级「提炼 agent」重读轨
迹。

### 3.4 skill 载体与治理

- 采用 SKILL.md 标准（YAML frontmatter + 正文，可附脚本）。落点与加载
  路径由执行者确认：repo 级 `.claude/skills/` 与 per-agent 位置皆可，
  取决于该经验归属全员还是单个 agent。
- 半自动提炼的交互设计参考官方 skill-creator 的引导循环（采集意图与触
  发条件 → 访谈边界情况 → 生成 SKILL.md）。
- 治理走使用反馈闭环，不做定时巡检：skill 走不通 → 该次任务大概率非一
  次通过 → 再次触发复盘 → 顺手修正或废弃该 skill。这是 Memp「Update
  环节」的最小实现。

### 3.5 验收样例（设计的试金石）

hermes PR 案例复演：agent 首次走通一条多步外部流程（过程有踩坑，非一次
通过）→ 触发复盘 → 流程固化为 skill 候补 → 人审落地 → 之后同 agent 再
走该路径时，直接调用 skill 而非重新摸索。交付时以此场景做端到端演示
（外部流程可用假环境）。留不住这个案例的实现即不合格。

## 4. 不做清单

- **不做规则库与自动注入引擎**（第三注入通道）：匹配问题（哪条规则该注
  入哪个任务）无好解，松则每任务背上下文税、紧则永不命中；且与 08-30
  否掉的「通用检查定义层」（打勾剧场）是同一物种。CLAUDE.md 与
  MEMORY.md 已经承担机器注入。
- **不做 AWM 式自动轨迹归纳引擎**：需要独立的轨迹读取/归纳基建；worker
  在场时自己复盘更便宜更准。若未来出现「海量历史轨迹回填」的真实需求
  再立项。
- **不做自动生成 skill / CLAUDE.md 直接生效**：所有候补必须过人审。垃
  圾技能比没有技能更毒。
- **不做记忆自动衰减 / TTL / 定时巡检**：人工策展即治理，反馈闭环即更
  新。
- **不做跨 agent 共享经验库**：用户已裁定排除。
- **不做每任务强制复盘**：一次绿过不触发。复盘疲劳会杀死策展，策展死
  则全盘皆输。
